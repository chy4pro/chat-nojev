## 正文（复制以下内容）

先说清楚它是什么：一个 **macOS 悬浮窗**，贴在微信窗口旁边。有新消息时，它读出最新那条，然后给你三样东西 ——

1. **这句话的真实意图**（派活 / 催进度 / 问进度 / 批评 / 要解释 / 闲聊 / 约会议 / 夸奖）
2. **风险分级 0–9**，带颜色（绿 / 橙 / 红）
3. **回复候选，按「话术」分组**：每种话术写 2 条（同一语气、不同措辞），组内按合适度排出 `#1`/`#2`；面板下方三个下拉框自己挑用哪几种话术（内置 9 种：高情商话术 / 贴吧老哥 v1.0 / 拒绝加班 / 卑微乙方 / 稳如老狗 / 已读乱回 / 职场黑话 / 阴阳怪气 / 理科直男），最多同时开三种。点一下「填入」直接进微信输入框。

起因很朴素：工作微信里消息一条条跳，有些话得看两遍才知道对方什么意思，回得慢了不合适，回错了更麻烦。我想要的是「瞟一眼就知道该怎么接」。

## 先说边界，免得误会

**它不注入微信、不 hook、不解密本地数据库、不自动发送任何消息。**

原理是**截屏 + OCR + 本地模型判断**：抓微信窗口画面 → 只对聊天区做 OCR（约 250ms）→ 本地小模型判断 → 输出到悬浮窗。也就是说，它对微信而言就是「屏幕上有个人在看」，没有封号风险那一说。

唯一一处「写」的动作是点「填入」时把候选写进微信输入框 —— 而且**也不发送**，要不要发、发什么，你自己按发送键。（这一步的技术选型踩了坑，下面讲。）

## 它是怎么做的：两层模型

关键设计是**判断和生成分开**，这是我觉得最值得分享的一点。

**判断层**要的是「概率」，不是「文采」。所以我用一个 **Jev 形状的小模型**（本地 `decider-2b`，也能换成 TypeSafe 官方的无嘴模型）：一次前向同时出「意图」和「风险」两个分布，全程不写一个字 —— 不写字的模型不会编，判断也就稳定。**本地跑，不需要联网、不需要 key**，MPS 上约 0.7 秒。

**生成层**才需要文采，所以交给任意 OpenAI / Anthropic 兼容端点（我用的 DeepSeek）。写完不直接给你，先**丢回本地模型排序** —— 因为 API 生成的候选里经常混着踩雷选项。

举个真实例子：一句「这做的什么玩意」（批评），生成的候选里有条「哈哈，老板，我这就改！」，本地模型把它压到第 3（6.6%），把「对不起，我马上改！」排到第 1（57.7%）。这就是为什么排序必须留在本地、而且必须由不讲情面的判断层来做。

两件事并行跑，所以**判断先上屏**（约 2 秒），候选晚一点到。

## 踩过的坑（这篇主要想分享这些）

### 1. 「填入」不能靠模拟 Cmd+V

第一版是老实做法：把候选写进剪贴板 → 把微信切到前台 → 合成一次 Cmd+V。看起来和用户自己按一遍完全等价。

坏在**「把微信切到前台」这件事在新版 macOS 上不可靠**。实测：`NSRunningApplication` 激活**返回成功但 `isActive` 始终是 False**；改用辅助功能接口设 `AXFrontmost`，同样返回成功却不生效 —— 现在的 macOS 不让后台/非激活进程抢焦点。我连跑 4 次填入，**3 次卡在这一步**。

更麻烦的是失败方式：粘贴是发给**最前台应用**的。判断失误放行的话，你的回复会被贴进当时真正在前台的那个窗口 —— 在别人的文档或聊天框里打字，这比「没填进去」严重得多。而且每次填入都会覆盖你的剪贴板。

**改法**：直接用辅助功能接口（Accessibility API）把文字**写进**输入框，不粘贴、不切前台、不碰剪贴板，写完**读回来确认**。三个问题一次解决，其中「读回来确认」最关键 —— 因为原来的实现里，**「按键发出去了」被我当成了「文字进去了」**：它返回「已填入」的时候，输入框其实还是空的，用户以为没点中，再点一次，然后被防重复保护拦住。**这个假成功是最难查的，因为它让面板和日志都显得正常。**

### 2. 微信的辅助功能树里有两个「输入框」

改成辅助功能写入之后，我写了个「取第一个 AXTextArea」的查找。测试全过。然后我发现**测试目标是错的**：

微信的聊天窗口里有两个 `AXTextArea` —— 侧边栏**搜索框**（实测 127×23）和**消息输入框**（实测 643×129）。搜索框层级更浅，广度优先「取第一个」先撞上它，于是测试文字全被写进了搜索框。

**而读回校验是自洽的** —— 读和写都走同一个错元素，所以互相印证、全部「通过」。这类 bug 最阴的地方在于：测试写得越认真，越容易相信它。

**改法**：取**面积最大**的那个，并且加一道尺寸下限 —— 宁可报「没找到微信输入框」也不猜。两者面积差了约 24 倍，不是需要赌的判断。

### 3. DeepSeek 现在能用的模型名，换一个就翻车

配置生成层时我照文档写了 `deepseek-v4-flash`，结果**候选区永远是空的**。查下去：

| 模型名 | 实测结果 |
|---|---|
| `deepseek-chat` | ✅ 0.7 秒，三条正常候选 |
| `deepseek-flash` | ❌ 只吐 457 字思考，**正文 0 字**，2.3 秒 |
| `deepseek-v4-pro` | ❌ 思考 499 字、正文 0 字，7.4 秒 |
| `deepseek-v4-flash` | ❌ 思考 293 字 + 正文 32 字，但正文是退化的重复 |

原因是这几个都是**带思考（thinking）的推理模型**：回答前先写一大段「想」，而我给的是 `max_tokens=300` —— 额度被思考吃光，正文一个字都没输出。把额度提到 2000 能让它出正文，但 `deepseek-flash` 要 **4.2 秒**、`deepseek-v4-pro` 要 **23.8 秒**，给聊天浮窗用完全不划算。

坑在于**报错方式**：面板只显示「候选生成失败: 空结果」，看起来像「没生成出来」，不像「模型选错了」。而且官方 `/models` 接口列出的两个模型恰好**都是**推理模型，唯一好用的 `deepseek-chat` 反而不在列表里。**「模型名合法」不等于「能出正文」，只能真跑一遍验证。**

### 4. 悬浮窗必须是「非激活式」，打包不能用 py2app

面板用 `NSWindowStyleMaskNonactivatingPanel` —— 点它不抢微信的焦点，你打字不被打断。

打包上我没用 py2app / PyInstaller：把 torch + transformers 冻进去会做出 **2–4 GB** 的 App。改成「启动器包」—— 包里只带源码（约 **400 KB**），首次启动时用 uv 在 `~/Library/Application Support` 建虚拟环境（依赖在 uv 缓存里，实测 3 秒）。**顺带还拿到一个独立身份**：屏幕录制 / 辅助功能这两个权限授权给「jev-chat-jarvis」这个应用本身，而不是启动它的那个终端 —— 这点用命令行跑是没有的。

### 5. 风险分级为什么显示「均值取整」

最初的风险显示是加权平均，会显示成 `4.7/9` —— 假精度。我一度改成「概率最高的那一档」，看起来更诚实，**结果实测打脸**：

decider-2b 的分布是平滑的，**最高档概率从不超过 0.4**（实测 8 条真消息，落在 0.18–0.39）。也就是说「最高档」永远没有真正占优，而且三条意思相近的「批评」消息会跳出 **1 / 3 / 6** 三个不同档位；反过来看均值是稳定的（派活 2.0–2.4、批评 3.0–4.0、闲聊 1.7）。

所以最后保留均值、**只把小数抹掉**：显示 `4/9`。数字该是估计值，就别写成测量值的样子。

## 实测数字（M1 Pro）

| 指标 | 数值 |
|---|---|
| 抓窗口画面 | ~180 ms |
| OCR（只扫聊天区） | ~250 ms（全窗是 650+ ms） |
| 判断（本地 decider-2b，MPS） | ~0.7 s |
| 候选生成（API，三条一次调用） | ~0.7 s（DeepSeek）/ ~1.7 s（智谱） |
| 消息 → 出意图 | ~2 s |
| 意图识别率（零样本，22 条中文职场消息） | **86.4%**（多数类基线 13.6%） |

**防刷屏**：新消息进来先只打个「有新消息」标记、保留上一轮结果；停稳 1.2 秒才开始分析，两次分析最小间隔 2 秒。群聊刷屏时面板不会满屏乱跳。

## 跑起来

**不想自己构建**：[Releases](https://github.com/jev-chat/jev-chat-jarvis-mac/releases/latest) 里有打好的 `.app`（约 400 KB）—— 下载、解压、拖进「应用程序」就行。第一次打开要**右键 → 打开**（没做 Apple 公证，直接双击会被 Gatekeeper 拦，只需这一次）。

想自己跑源码：

```bash
git clone https://github.com/jev-chat/jev-chat-jarvis-mac.git
cd jev-chat-jarvis-mac
./start.command          # 会自动用 uv 建环境（没装 uv 也会自己装）
```

**首次要两个权限**（都会弹系统框引导）：

- **屏幕录制** —— 读屏必需，授权后**要退出重开**（macOS 要求重启进程才生效）
- **辅助功能** —— 「填入」按钮必需

**判断层不需要 key**：不填就用本地小模型（首次下载约 7GB，之后离线可用）。**只有写候选回复的那层需要配一个 key**，任意 OpenAI / Anthropic 兼容端点都行：

```bash
mkdir -p ~/.config/jev-jarvis
cat > ~/.config/jev-jarvis/env <<'ENV'
export OPENAI_API_KEY="sk-你的key"
export OPENAI_BASE_URL="https://api.deepseek.com"
export OPENAI_MODEL="deepseek-chat"
ENV
chmod 600 ~/.config/jev-jarvis/env
```

密钥只放在仓库外这个文件里。**两层 key 都可以不填** —— 都不填也会跑，只是候选区空着。

## 已知限制（V0 的边界）

- **只判最新一条**（上下文取了最近 4 条喂给判断层，但不做会话级理解）
- **只在 macOS**，且微信客户端改版可能导致布局识别失效 —— 有兜底提示，但得跟着改
- 只在**你自己屏幕、你自己账号**上自用。把它装到别人机器上读别人的聊天记录，是另一回事，这个项目不为那种用法背书
- 消息内容会**发给生成层那个第三方端点**（判断层全程本地、不出网）。介意的话生成层可以换成本地 Ollama，代价是慢
