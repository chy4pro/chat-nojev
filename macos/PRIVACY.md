# 隐私与数据说明

jev-jarvis 的核心原则是**纯只读**：不注入、不 hook、不解密本地聊天数据库、不自动发送任何消息。
这一页说清另一件事：**哪些数据会离开你的电脑、发到哪里**。这一版只有一个模型、一次调用：
意图、风险、行动建议和候选回复都来自它，所以**判断也跟着出网**。配本地 Ollama 时整个应用不出网。

> 与上游的差别就在这里。上游有两层：判断层默认跑在本机（`Mapika/decider-2b`，不联网、不要 key），
> 只有候选回复那一层出网。这一版把判断、排序、候选三件事合成一次调用，本地那个判断模型删掉了——
> 同一条消息仍然只发一次、发给同一个服务商，但**不再有「判断永远不出网」这条保证**。
> 在意这一点的话：方式一（本地 Ollama）能把整条链都留在本机。

## 不会离开你电脑的部分

- **屏幕抓图与 OCR**（截图型应用）：只读你自己屏幕上、你自己聊天窗口的内容；抓图仅在内存与临时目录
  中处理，不保存到磁盘、不随日志记录。
- **QQ 消息读取**：读系统无障碍树里的文字节点，全程在内存，不截图、不 OCR。
- **日志**：不含消息正文、会话背景与候选回复文字；模型服务的错误正文也不回显到日志。
- **密钥**：保存在 `~/.config/jev-jarvis/env`（权限 600），不上传。

## 本地会话数据

历史记录默认关闭。开启后，每个可确认聊天仅保留实际识别的最近 100 条已发送消息（含本人和其他成员），不导入或补齐完整聊天记录。多行背景独立保存，关闭历史仍可使用背景与当前画面。

历史与背景以明文保存在本机的 `~/Library/Application Support/jev-jarvis/conversations.json`，源码运行与打包 `.app` 使用同一位置，文件权限为 `600`。该目录在 Git 仓库之外，聊天内容不会进入代码提交。按聊天标题隔离，首版要求单账号、唯一标题；标题不确定时不读写，改名建立新会话。

推理默认使用最新 20 条，可调 1—100，包含当前消息；背景不占条数。请求可能因长度预算进一步裁剪，本地原文不变。关闭开关保留数据并停止记录和历史注入；在「会话记录与背景 → 管理记录」清空所选会话／全部记录会保留背景；清空背景编辑框后保存可单独删除背景。删除应用不会自动删除会话数据文件。

**本地保存不等于推理不外发。** 推理使用用户配置的那一个模型服务，包含配置的中转；服务地址可在模型设置页配置。意图、风险和候选回复来自同一次调用，所以它们走的是同一个服务、同一条链路——没有「判断留在本机」这条回退。模型服务配置变更需重启生效。应用不增加历史同步、项目后台存档或遥测上传，也不保证模型服务或中转服务零留存。

## 那一次调用：聊天文字发到哪里

悬浮窗要出「意图 / 风险 / 候选回复」，必须把当前待回复消息、选取的会话上下文和人工背景发给一个聊天模型；候选的排序分也在同一次回答里，不额外发一次。发给谁由你的配置决定，
按隐私程度从高到低有三档：

### 方式一（隐私最优）：本地模型，完全不出网

生成层配本地 Ollama：`OPENAI_BASE_URL="http://localhost:11434/v1"`、密钥 `ollama`、模型如
`qwen2.5:7b`（详见 README「配置」一节）。此时聊天文字只在本机内传输，**不出网**；模型文件在
Ollama 自己的目录（`~/.ollama`），由 Ollama 自行管理，本项目不代为下载。

### 方式二（推荐）：配置你自己的 API key

按 README「配置」一节填 `OPENAI_API_KEY` / `ANTHROPIC_API_KEY`（DeepSeek、智谱等均可）。
此时聊天文字**直接从你的电脑发送给你自己选择的服务商**，不经过本项目作者的任何服务器。

### 没有内置通道

jev-chat-jarvis-mac 的打包版内置了一把共享 key，不配 key 时走原作者自建并运营的模型中转（明文 HTTP）。
这一版把它留空了（`src/builtin.py`）：那是原作者的服务和额度，派生版不把自己的用户接过去，
也不替别人的服务器做数据承诺。**不配 key 就不出候选**，启动时弹窗提示去配置——聊天内容只会发给
你自己在方式一或方式二里选的服务商。

## 使用与免责

- 候选回复由模型自动生成，仅供参看；是否采纳、是否发送完全由你决定，本项目不对生成内容的
  准确性与得体性负责。
